# PRESPEC_WP9: pharmacovigilance safety screen of the MLSS drugs and drug pairs (7 Nov 2026)

**Status.** Written and fingerprinted BEFORE any report count for an MLSS drug was retrieved. Before the fingerprint, one syntax probe of the API was run with drugs that are not in the screen (metformin, sitagliptin) and with generic reaction terms (`results/probe_log.txt`; it only showed that every query form below works, about 1.5 s per request). The fingerprint line is in `../PROTOCOL_v2_SHA256.txt`. A later change is a dated entry in section 9, never an edit of sections 1 to 8.

## 1. What this is, and what it is not
An **annotation** of the 18 drugs and the 77 cross-target pairs that the manuscript proposes for dose-response testing (MLSS ranks 1 to 77), using public spontaneous-report data. It is **not a prediction** of toxicity or adverse effects: there is no model, no ground truth and no test of the MLSS ranking. Spontaneous reports give neither incidence nor causality; the screen reports disproportionality signals and co-reporting counts and nothing else. It was added at the user's request (7 Nov 2026) for the JTM collection on computational modelling and network medicine in drug toxicology and pharmacovigilance. It is post hoc with respect to the MLSS (the ranking was fixed earlier and is not changed) and pre-specified with respect to the data retrieval and the rules below. Framing in all texts: computational, hypothesis-generating; the words "toxicity prediction", "adverse effect prediction", "safe", "unsafe" and "risk" are not used for its results.

## 2. Inputs fixed from earlier work (read only)
* Drugs, ranks and scores: `../wp3_mlss/mlss_scenario_scores.csv` (columns `Rank`, `Combination` = "drug A + drug B", `reported_MLSS`); target gene of each drug: `../wp3_mlss/direction_table.csv` (rows with `used_in_mlss` True; GLP1R: 7 drugs, CACNA1D: 11 entries).
* **Cross-target pairs** = pairs whose two drugs have different target genes: 77 pairs (7 x 11), ranks 1 to 77. Same-target pairs (ranks 78 to 153) are not proposed in the manuscript and are not screened. **Top 15** = the 15 best-ranked combinations as reported.

## 3. Source and retrieval
* openFDA drug adverse event endpoint (FDA Adverse Event Reporting System, FAERS), `https://api.fda.gov/drug/event.json`: public, no key, plain HTTPS GET, nothing about the user is sent; at most 2.5 requests per second; retries with back-off on time-outs and HTTP 429 or 5xx; at most 850 new requests per run because the limit without a key is 1000 per day (a longer run is simply re-run on the next day; every response is cached and never requested twice).
* Every raw response is stored (`results/raw/`, JSON with its URL and retrieval time). After the last retrieval, one fingerprint over all raw files (sha256 of the sorted list of file names and file hashes) is written to `results/RAW_SHA256.txt` and to `../PROTOCOL_v2_SHA256.txt` BEFORE the analysis script is run. The analysis reads only the saved files (offline). The data are a snapshot (`meta.last_updated` is recorded); counts change with every FDA update, which is why the raw files are the record.
* Counts are numbers of **reports** (`meta.results.total`), not events; a report counts once per drug and once per event group however often it lists them.

## 4. Drug mapping (fixed)
* A report belongs to a drug if `patient.drug.openfda.substance_name` contains the lower-case active-ingredient name as a phrase (any role: suspect, concomitant or interacting; reports without the harmonized `openfda` fields are not seen, a limitation). Search terms are the MLSS drug names in lower case, except that `(S)-nitrendipine` is searched as `nitrendipine` (an enantiomer has no FAERS entry of its own): the two MLSS entries share their counts, said wherever they appear.
* GLP1R drugs: liraglutide, semaglutide, exenatide, dulaglutide, lixisenatide, albiglutide, glucagon. CACNA1D drugs: amlodipine, bepridil, clevidipine, felodipine, isradipine, nifedipine, nilvadipine, nimodipine, nisoldipine, nitrendipine, (S)-nitrendipine. That is 17 search terms for 18 MLSS entries and 70 distinct search-term pairs for the 77 cross-target pairs.
* A drug with fewer than **100** reports in all is **not evaluable** (no event statistics; listed).

## 6. Statistics (fixed)
Notation: N = all reports; n_d = reports of drug d; E_g = reports in group g; a_dg = reports of drug d in group g.
* **Single-drug signal.** Reporting odds ratio ROR = [a/(n_d - a)] / [(E_g - a)/(N - n_d - E_g + a)] against all other reports; 95% interval by Woolf's method on the log scale (0.5 added to all four cells if any cell is 0). **Signal** if a_dg >= 3 and the lower limit is above 1. The proportion a_dg / n_d is reported next to it. The comparator contains the other drugs of the same class, so a class-wide effect shows as a signal for every member.
* **Pair (A, B), cross-target.** n_AB = reports that list both drugs (search terms joined by AND). **Evaluable** if n_AB >= 20; only then the counts a_AB,g are retrieved for the 8 groups. p_AB,g = a_AB,g / n_AB with an exact (Clopper-Pearson) 95% interval; p_A|notB,g = (a_A,g - a_AB,g) / (n_A - n_AB), and p_B|notA,g likewise. **Co-report excess** (descriptive flag, not an interaction test) if a_AB,g >= 3 and the lower limit of p_AB,g is above the larger of p_A|notB,g and p_B|notA,g. No adjustment for age, sex, indication, dose, co-medication or multiplicity: the number of flags among the evaluable pairs and 8 groups is reported with the statement that false flags are not controlled.
* **No test of the MLSS ranking.** With 18 drugs of two near-identical classes a test of "ranking versus safety signal" would have negligible power, so none is run. Descriptive only: for each group, the number of the top-15 pairs and of all 77 pairs in which at least one of the two drugs has a single-drug signal in that group.
* **Reported regardless of outcome:** all counts, all non-evaluable drugs and pairs, every flag, every failed request. No group, term list, threshold or mapping is changed after the first retrieval; a drug that returns zero reports is reported as such.

## 7. Planned limitations text (to be adapted, nothing here is a result)
Spontaneous reporting (under-reporting, stimulated reporting for newer drugs, duplicates, no denominators or exposure), mapping through the harmonized `openfda` fields (reports without them are not seen), confounding by indication, age and co-medication (a drug used to treat an event, such as glucagon for hypoglycemia, is expected to be flagged for it), disproportionality is not risk, pair counts are sparse and the flag is conservative and uncorrected, no information on dose or timing, class-wide signals because the comparator contains the class, a snapshot of a database that changes every quarter.
